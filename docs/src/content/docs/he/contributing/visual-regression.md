`npm run test:visual` מצלם 40 צילומי מסך — עשרה מסכים, באנגלית (LTR)
ובעברית (RTL), בערכת הנושא הבהירה ובכהה — ומשווה כל אחד לתמונת הבסיס שלו.
שינוי בפיקסלים שאף אחד לא התכוון אליו מכשיל את ההרצה; כך גם מסך בלי תמונת
בסיס.

## הרצה ראשונה במחשב

```bash
npx playwright install chromium
npm run visual:approve -- visual   # בונה, מגיש את dist/, כותב visual/__baselines__/<platform>/ אחרי שמקלידים "approve"
```

פותחים כל PNG, ואז מכניסים את התיקייה ל-commit. אף הרצה אחרת לא כותבת תמונת
בסיס: תמונה חסרה היא כישלון, במחשב שלכם ובשער, ו-`visual:approve` מסרב לרוץ
ב-CI. מכאן והלאה:

```bash
npm run test:visual
```

כישלון משאיר את התמונה הצפויה, בפועל וההבדל ב-`visual-results/`
(`visual-results/report/index.html`).

## מה שומר על הצילומים יציבים

- גרסת הייצור, מוגשת עם `vite preview`.
- Chromium בלבד, ‏1280×800 ב-1×, שפת דפדפן en-US ואזור זמן UTC.
- פתק קבוע (באנגלית או בעברית), שעון קבוע, בלי service worker.
- הגופנים של האפליקציה עצמה; אנימציות, מעברים, פסי גלילה והסמן כבויים.
- החלקים שתלויים במחשב (האם מודל מקומי רץ) מוסתרים.

תמונות הבסיס הן לפי פלטפורמה: משווים על אותו סוג מחשב שכתב אותן. כל צילום
נכשל גם אם הדף רחב מהחלון — באג ה-RTL הנפוץ ביותר.

## שינוי מכוון

מריצים `npm run visual:approve -- visual`, בודקים את קובצי ה-PNG שהשתנו
ומכניסים אותם ל-commit יחד עם השינוי. אותה פקודה מקבלת גם `print`, ‏`canvas`,
‏`slides` ו-`smoke` למבחני ה-e2e שמשווים צילומי מסך.

## האם השער עובד?

`visual/selftest.visual.ts` כותב תמונת בסיס זמנית של התצוגה המפוצלת, מזיז
את סרגל הכלים ב-3 פיקסלים ובודק שההשוואה נכשלת.

## מטריצת RTL

`visual/rtl.visual.ts` מוסיף שישה צילומים של פתק מטריצת ה-RTL
(`e2e/rtl-note.ts`): התצוגה ו-WYSIWYG בעברית, בהיר וכהה, והתצוגה על iPhone 14
ועל Pixel 7.

## ‏Safari, ‏Firefox ו-Edge אמיתיים (Percy)

ה-baselines המקומיים מצולמים ב-Chromium. באגים של פריסת RTL מופיעים בעיקר
ב-Safari, ולכן כל קידום של main נבדק גם ב-Percy, שזמין בחינם בתוכנית הקוד
הפתוח של BrowserStack. ‏Percy מצלם 30 מסכים, כל אחד בעברית ובאנגלית, בהיר
וכהה:

- עשרת המשטחים שלמעלה;
- פתק מטריצת ה-RTL;
- תשע-עשרה תצוגות שנפתחות בפקודות שלהן: הגדרות, גרף, קנבס, חיפוש,
  היסטוריית גרסאות ועוד (`visual/percy-surfaces.ts`).

‏Playwright לוכד ב-Chromium את ה-DOM של כל מסך (`visual/percy.percy.ts`).
אחר כך Percy מרנדר את ה-DOM הזה ב-Chrome, ‏Firefox ו-Safari אמיתיים (וגם
ב-Edge), ומשווה ל-baseline המאושר של main. ה-baselines המקומיים נשארים כמו
שהם.

```sh
PERCY_TOKEN=… npm run visual:percy             # ‏30 מסכים × 4 מצבים
PERCY_TOKEN=… npm run visual:percy -- --canary # בדיקה עצמית: טקסט RTL זז ב-2px
```

בניית הקנרית מזיזה ב-2px את טקסט ה-RTL בתצוגה. היא חייבת להראות שינויים
בכל דפדפן, ואף פעם לא מאושרת. מחוץ ל-`percy exec` החבילה מדלגת על עצמה.
הטוקן נשמר במאגר הסודות של הסוכן, וההרצה היא חלק מצינור השחרור (W7.21), לא
GitHub Actions.
