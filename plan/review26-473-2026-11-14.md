## What changed (from reading)

The change is in `redactionTree.ts` and `redaction.ts`, 51 lines in all.

**Two cases, for an opening tag the preview reads inside another mark's tag:**
- **The host mark is a close to the export:** it becomes that opening mark, and records the tag it stands for in `at`.
- **The host already opens, or already stands for a tag:** a separate opening mark is added at that tag. The export already removes from the host on, so the extra open only keeps the passage open longer, which fails closed.

**Each such mark opens once, at its tag:**
- In the tree pass, `asText` skips a mark whose `at` lies further on.
- The tag token at `at` then opens it as an element.
- The text pass opens both kinds as elements.

## RR26-473-1 (INFO, from reading): `at` is left in the wrong offsets

- **Where:** `redactMarks` (`redaction.ts:108-111`). It maps `index` and `end` back to the note, but not the new `at`.
- **Effect:** `at` stays in the prepared text's offsets. That is harmless today, because only the two passes read it, and they run before the mapping. A later consumer would get a wrong offset.
- **Fix:** map `at` along with `index` and `end`, or drop it before returning.
