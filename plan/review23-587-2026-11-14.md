### RR23-587-1 (LOW, confirmed): `privateRemoved` does not fail closed

**What it is:** `privateRemoved` (`standardSite.ts`) is a regex pass. It counts every `</redact>` it finds as a close, including one inside an attribute, a code span, a comment or a container.

**Effect:**
- The six shapes B5–B10 leak through direct calls in every build.
- In this build they also leak on the app path. But this build has no #473, so the app has no redaction feature to leak from.
- With #473 in the train, `publishNote` is safe (12/12).

**The overclaim:** the doc comment says "no caller can hand a raw note to a record". That holds only for the simple shapes.

**Fix:** reach #473's synchronous `prepareForExportSync` through an eager `import.meta.glob` inside `privateRemoved`, or make `documentRecord` accept only a branded, publish-ready string.

### RR23-587-2 (LOW, from reading): the door seam can fail silently

- `import.meta.glob('../storage/exportReady*.ts')` falls back to the regex pass if #473's file is renamed or moved.
- **Fix:** add a test that fails when `src/storage/exportReady.ts` exists but the seam doesn't find it.

## 2. One note at a time, confirmation first

**From reading** (`standardSiteActions.ts`, `commands/domains/export.ts`):
- **The commands.** "Publish…" and "Remove…" are palette commands that act on the open note only, which is snapshotted before any `await`. Nothing is selected by default, and nothing is published in bulk.
- **The order.**
  1. `account()` may first prompt for the handle and site, which stays local.
  2. Then `uiConfirm` shows a message that says **public, permanent, relays keep copies**.
  3. Declining returns before any password prompt or request.
- **The fetch.** `atprotoFetch(() => asked)` holds the same memoised promise, so no request goes out without that answer and parallel requests can't ask twice.
- **Unpublish** uses the same order.

## 3. App Password and refresh token

**From reading:**
- **The App Password:**
  - It is typed into a `type=password`, `autocomplete=off` field (the new `PromptDialog` option).
  - It is used for one `createSession` to the `bsky.social` entryway, and it stays a local variable.
  - `lumen.atproto.appPassword` is gone from the secret list, and no code stores it.
- **The refresh token:**
  - It is the only stored credential (`lumen.atproto.refreshJwt`, secret store), and it is replaced whenever a new one arrives.
  - `resume` sends it only to `bsky.social`.
- **The access token** lives only in memory.
- **Errors** carry the server's message, never the password or a token.
- The PR's own test checks that the fake PDS sees the password only in the `createSession` body (10/10).
