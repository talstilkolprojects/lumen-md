## Open sources (#589, #591, #592, #593)

### 1. Confirm-first gate and ledger

**What the code does** (`src/sources/open/gate.ts`):
- Every source request goes through `withGate` or `gatedFetch`. Each such fetch:
  1. checks `enabled()` on every call, and throws `SourceOffError` before asking anything;
  2. asks once;
  3. then sends through `ledgerFetch({force, consent: true})`.
- Every caller passes `enabled: () => isSourceEnabled(<source>)`:
  - Knesset: `findLaw`, `findBills`;
  - data.gov.il: `search`, `addResource`, `addSeries`, `refresh`;
  - Ben-Yehuda: `getCatalogue`, `download`.
- The dialog (#593) uses its own `dialogFetch`. It checks each request's host against the sources that are on, and ledgers each one under its own source's reason (`open/app.ts:15-29`).
- Offline paths make no request: saved laws, "Ask the law", the dataset block, and the library index.
- By default Sefaria is on and the three new sources are off (`gate.ts:67`).

**Tests** (`t593/gate.mjs`, the real gate.ts with a stub base and a stub confirm):
- **G1 pass:** a source that is off sends nothing and never asks.
- **G2 pass:** "no" sends nothing.
- **G3 pass:** nothing is sent before "yes" resolves.
- **G4 FAILS:** two requests in parallel on one gate open **two** confirmations. That is RR20-2.

**The PR's own tests (vt3m):**

### RR20-2 (LOW, confirmed): the gate asks once per request, not once per search

**Where:**
- `gate.ts:44-51`: `asked ??= await opts.confirm()` stores the answer, not the pending promise, so every call made before the first answer resolves opens a confirm of its own.
- `search.ts:103-127`: `searchOnline` starts the Knesset and the data.gov.il requests in parallel.

**Effect:** one dialog search shows two prompts. The answers then apply per request: answering yes and then no sent the Knesset request and refused the data.gov.il one. Nothing is sent before a yes.

**Fix:** memoise the confirm promise.

### 2. Airplane mode

**`t593/airplane.mjs`** (Chromium). It installs the real `installPrivacyLedger` and then the real `installAirplaneMode`, in `main.tsx`'s order, and calls the gated fetch. The page is served with the worktree's `public/_headers` CSP.

- **P1 pass (#593):** with the switch on, 7 gated requests reached nothing. They went to the Knesset, data.gov.il, CBS, the raw GitHub dump, bsky.social, plc.directory and a `*.host.bsky.network` PDS. The airplane CSP refused each one, and the attempt log records each refusal.
- **P2 FAILS (#593):** a gated request already in flight when the switch went on **completed** and was **not counted**.

### RR20-1 (MEDIUM, confirmed): airplane mode misses ledger requests that are in flight at the switch

**Where:**
- `privacyLedger.ts:431-432`: `ledgerFetch` sends through `unwrappedFetch`.
- That is the fetch `installPrivacyLedger` captured (`:630-631`), and `main.tsx:36` installs the ledger **before** airplane mode (`:45`).
- So the gated sources' requests never pass through airplane's fetch wrapper.

**What still holds:** new requests are refused by the airplane CSP.

**What breaks:**
- A request already in flight is neither aborted nor recorded as in flight. That covers a Ben-Yehuda per-author download (four at a time), a data.gov.il table, and a Knesset query.
- The certificate then omits it, although it promises "every request … still open when the switch went on: counted … then aborted".
- Sefaria's existing path has the same gap.

**Fix:** let airplane wrap the ledger's base fetch through an exported hook, or have `ledgerFetch` call the current `window.fetch`, with a flag so the request isn't recorded twice. The fix belongs in #589, the lowest PR of the stack.

### 4. Imported content

**Rendering:**
- Imported text becomes ordinary notes, so the preview's sanitizer applies (`rehypeSanitizeRaw`).
- Remote images and media are click-to-load (`remoteImages.ts`).
- Script and HTML injection into the preview is therefore covered.
- What is not covered is the integrity of the note itself.

### RR20-3 (LOW, confirmed): remote fields are written into notes without escaping

**Where:**
- Ben-Yehuda: `genre` is written raw into frontmatter, and the title into `# title` (`library.ts:84`, `:91`).
- Knesset: `# name` (`store.ts:65`).
- data.gov.il: `dataset`, `updated` and `id` inside the ```dataset fence (`snapshot.ts:97-110`).

**Tests** (`t593/inject.mjs`):
- **I1 FAILS:** a catalogue `genre` with a line break added `rights: all-rights-reserved` to the work note's frontmatter.
- **I2 FAILS:** a dataset slug with a line break closed the fence and put `<b>Z1Z</b>` into the note.

**Severity:** the sources are government publishers and the project's own dump, served over TLS, so this is low.

**Fix:** JSON-quote every field, and strip line breaks from headings.

### RR20-4 (LOW, confirmed): a dataset block can show any vault file

**Where:** `parseBlock` (`snapshot.ts:114-134`) and `readSnapshot` (`datagov/app.ts:54`) accept any vault path as the snapshot.

**Effect:** a ```dataset block in a shared or received note renders any file of the **reader's** vault as a table, both in their preview and in what they print. **I3 FAILS** (`snapshot: Private/diary.md` was accepted).

**Fix:** accept only `Data/(datagov|cbs)/<safe id>/<date>.csv`.

### RR20-5 (LOW, from reading): integrity of the per-author download (Ben-Yehuda, `core.ts:23-75`)

- **Integrity:** files come from an unpinned `master`, with no hash and no size check, and `res.text()` is unbounded.
- **Failure handling:** `Promise.all` rejects on the first failure while the other workers keep writing.
- **Cancellation:** `download()` passes no AbortSignal.
- **Rights:** the "public domain only" filter trusts the catalogue saved in the vault, which a synced or shared vault can edit.

**Fix:**
- Pin a commit and record its hash.
- Cap the size of each response.
- Pass an AbortSignal through `download()`.

**Malformed dumps are handled:**
- `parseCatalogue` skips rows with a bad id or path.
- An empty catalogue throws.
- data.gov.il tables are capped at 1,000 rows.

### 5. Rights and attribution on export

**What survives export:**
- Insertions carry their credit as body text: a Ben-Yehuda quote (`library.ts:174-177`), a Knesset citation (`store.ts:176-179`), and the data.gov.il/CBS attribution line under the block (`snapshot.ts:154-166`). Body text survives every export.
- Nothing in these PRs strips that text.

### RR20-6 (INFO): credit that only lives in frontmatter

- A downloaded **work note** and a saved **law note** keep their rights and credit only in frontmatter.
- The pipeline drops frontmatter on export, so a PDF or HTML of the note itself has no credit.
- Both are public domain or section 6, so no licence requires the credit; Project Ben-Yehuda asks for it.
- **Fix:** add a visible credit line to the work note body.

**Note:** `src/sources/` is not in CODEOWNERS, so the gate (`src/sources/open/gate.ts`) is not a sensitive path. #592's and #593's receipts therefore have no sensitive files to cover. Add `src/sources/open/gate.ts`, and the publish paths below.

## W7.19: #596 and #587

### #596 (feat/atproto-publish)

**CSP:** adds `https://bsky.social`, `https://plc.directory` and `https://*.bsky.network` in all 5 sources; `headers --check` passes.

**Airplane:** P1 passes. Its client uses the global fetch, which airplane wraps.

**The PR's own tests:** `atprotoPublish` 9/9, `csp` 17/17.

#### RR20-596-1 (HIGH, confirmed): the public record is built from the raw note

**Where:**
- `PublishSiteDialog.tsx:113`: the notes come from `readAllNotes()`, raw.
- `publish.ts:72-100`: `publishNotes` passes them unchanged.
- `standard.ts:59-68`: `documentRecord` puts the note's plain text (up to 100,000 characters) in `textContent`, and its first paragraph in `description`.
- `prepareForExport` is never called.

**Test** (`t596/redact-record.mjs`, pure):
- **A1 FAILS:** the record carries the `<redact>` passages and `%% … %%` comments (Z1Z, Z4Z, Z5Z). HTML comments are dropped by `plainText`.
- **A2 FAILS:** the description carries a redacted first paragraph.

**Why it is high:**
- The base (verify/train-2) doesn't have #473 yet. Once both are in the train, this is the one export door that skips redaction, while the static site built from the same notes is redacted.
- The target is public and federated. Relays and AppViews keep copies, so "Remove" can't take it back.
- #481's CODEOWNERS lists export doors precisely because each one must call `prepareForExport`.

#### RR20-596-2 (MEDIUM, from reading): one click publishes the whole vault

- The picked notes default to every note in the vault (`:116`).
- The atproto checkbox persists between sessions.
- The records are written **before** the deploy, even when the target is "zip", a local download.
- No confirmation states the count, or that the records are public and copied by relays.

#### RR20-596-3 (LOW, from reading): the App Password is kept longer than needed

- The App Password is stored after every successful sign-in (`client.ts:113`), although the stored refresh token is enough.
- The password goes to the PDS that the DID document names (`client.ts:110`). Only the CSP keeps that to Bluesky hosts today.

#### RR20-596-4 (LOW): the wildcard is wider than needed

- `*.bsky.network` is broader than Bluesky's PDS hosts, which are all `<name>.<region>.host.bsky.network`.
- The `bsky.social` entryway can also take the session and the repo writes, which needs no wildcard at all.
- `cloudRoutes.test.ts` has no AT Protocol route.

#### RR20-596-5 (INFO): password hygiene otherwise holds

- Not logged.
- Not in the ledger, which records only host, method and byte counts (`privacyLedger.ts:325-342`).
- Not in errors: `AtprotoError` carries the server's message.
- Stored encrypted in the secret store (AES-GCM, or the OS keychain on desktop).

### #587 (feat/standard-site-publish)

**CSP:** adds `https://bsky.social`, `https://*.host.bsky.network` and `https://plc.directory` (the narrower wildcard); `headers --check` passes.

**Airplane:** P1 passes.

**The PR's own tests:** `standardSite` 6/6, `csp` 17/17.

**Password and tokens:**
- `login` sends the App Password only to the entryway (`bsky.social`) or to a service the caller names (`standardSite.ts:194-204`), never to a host taken from a DID document.
- The session tokens are kept in memory only.
- Only the App Password goes in the secret store.

#### RR20-587-1 (MEDIUM, from reading): a library with no caller

- Nothing in the app calls `login` or `publishNote`, so there is no UI.
- The user-action gate, the secret-store use, and "`markdown` is the export door's text (redacted)" (`:221`) are therefore promises, not code.
- The record's `content.text` carries the **whole** Markdown, so a caller that passes the raw note would publish everything.
- **Fix:** run `prepareForExport` inside `publishNote` itself, not in the caller, and gate publishing behind an explicit per-note Publish with a confirmation.

#### RR20-587-2 (LOW, from reading)

- `pdsOf` (`:184-187`) doesn't require https.
- `atprotoFetch` is `ledgerFetch`, so RR20-1's in-flight gap applies here too.

### Recommendation: keep #587, mark #596 superseded

**Why #587, on the three security grounds asked:**
- **Narrower CSP:** `*.host.bsky.network` instead of `*.bsky.network`.
- **Password and token handling:**
  - #587 sends the password only to a fixed entryway and keeps the session tokens in memory.
  - #596 persists both the App Password and the refresh token, and sends the password to a host taken from the DID document.
- **User-action gating:** neither PR is right yet.
  - #596 gates on the Publish click, but it defaults to the whole vault and publishes the raw text (high).
  - #587 has no UI yet, so its gate is still to be written.
  - #587's design is the one to finish: one note at a time, and records built from the export door's text.

**Before #587 merges:**
1. Call `prepareForExport` inside `publishNote`.
2. Add the per-note Publish / Update / Unpublish actions behind a confirmation that says the record is public and permanent.
3. Add a cloud route for it.
4. Add `src/publish/standardSite.ts` to CODEOWNERS.
5. Require https in `pdsOf`.

#596's dialog (handle, site address, Bridgy Fed hint) can be ported onto #587, without its default of selecting every note.
