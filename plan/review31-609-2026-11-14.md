## L1: binding the proof to the channel (fixed)

**What changed:** `proofData` (`rpc.ts`) now ends with `|fp=<host>,<peer>`. `channelBinding` orders the pair so both sides sign the same string.

**The role labels are unchanged:** `lumen-lan:1|host|…` and `|peer|…`.

**Where the fingerprints come from:** the actual connection.
- `link.ts` reads them with `sdpFingerprint` from `pc.localDescription` and `pc.remoteDescription`. Those are the descriptions the connection was set up with, and the DTLS handshake checks the other side's certificate against the remote one.
- They are not read from the code text a user or the network handed over.
- The host passes `link.fingerprints` to `attach` (`LanPairing.tsx:311`). The joining side passes them to `remoteLanProvider` (`index.ts`).

**#607's host → peer path:** it authenticates through this same `proofData`, so the binding covers it once both PRs are in the train.
- The two branches conflict in `remoteLanProvider`'s `opts` and in the `Conn` literal. Resolve by union, as the PR body says.
- Then rerun `lanProofBinding` and review 28's `r28-607` tests on the merged train (L1c).

### L1a: is a code from the fingerprints alone sound? Yes

It works as a short authentication string, and it is a sound choice here for three reasons:
- It needs no key. The joining device has none until it unlocks, and the code has to be shown before the first sync.
- Once the vault is unlocked, the proof covers the same fingerprint pair.
- A party in the middle would need two connections that agree on 8 digits. That is about 10^8 certificate tries within the pairing's timeout.

The joining device waits for the user's "same code" before it adopts the link, and the host shows the code next to each device.

### L1b (low): fingerprints that can't be read

**Where:** if a side can't read fingerprints, the binding becomes `-`, and the joining screen skips the comparison (`LanPairing.tsx`: `if (code && …)`).

**Why it is low:** a real WebRTC connection always has fingerprints. And a `-` on one side only fails the proof, so it fails closed.

**Fix:** a pairing found over the network should be refused rather than continue without a code. Keep `-` for in-memory tests only.
