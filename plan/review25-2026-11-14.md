## 1. `wrapLedgerTransport` (RR20-1: fixed)

**What it does** (`privacyLedger.ts:448`, `airplane.ts:311`):
- `installAirplaneMode` builds its guard once.
- It installs the guard on `window.fetch`, which is the ledger wrapping the original fetch.
- It also installs it on the ledger's own transport: `unwrappedFetch`, used by `ledgerFetch` (open sources, Sefaria, agents, PlantUML), and `rawFetch`, used by `guardedFetch` (the clipper, monitoring).

**Every path is covered:**
- The window path is guard → ledger → original. The ledger path is ledger → guard → original.
- Each request is therefore recorded once and guarded once.

**No window at the switch:**
- The guard decides at call time and registers the request as in flight synchronously, before any `await`.
- So a request either starts before the switch and is aborted with it, or meets the switch and is blocked.
- A `withLedger` that awaits before calling its base also calls the guard after the switch.
- Response bodies stay abortable through `bodies`.

### RR25-1 (INFO, from reading)

- **Where:** `ledgerFetch` (`privacyLedger.ts:431-432`).
- **What happens:** it reads `unwrappedFetch` when it is created, not when it is called. A `ledgerFetch` created before the airplane chunk loads at startup keeps the unguarded base.
- **Why it is only info:** every call site creates its `ledgerFetch` per request today.
- **Sefaria:** its own lookup gate (`sefaria/app.ts:34-38`) keeps RR20-2's `asked ??= await confirm()` pattern.
- **Fix:** read `unwrappedFetch` at call time inside `ledgerFetch`, and memoise Sefaria's confirm promise.

## 2. SHA-256 pins

### The dataset file (#591, RR20-4: fixed)

- `parseBlock` accepts only `Data/<source>/<its id>/<date>.csv`, the exact path `snapshotPath` would write.
- `verifiedSnapshot` hashes the very string it returns, so there is no TOCTOU.
- The hash sits in the note itself, next to the path. It stops a block from showing a different file at that path; it does not stop anyone who can edit the note.
- `refreshBlock` reads the old snapshot without checking its hash, but only to compute its diff, and under the same path rule. That is info.

### The Ben-Yehuda catalogue (#592, RR20-5: fixed)

**From reading:**
- The dump is pinned at commit `5e4277fe…`, and the catalogue at `CATALOGUE_SHA256`.
- **The saved catalogue is re-verified on every load:** `catalogue()` hashes the saved copy before each parse, and uses it only when it matches.
- **No TOCTOU:** the bytes that are checked are the bytes that are parsed and written.

**`t/pin.mjs`** (stub fetch, in-memory store), 5/5 pass:
- **C1:** a tampered saved catalogue (an edited row plus a copyrighted work) gives 0 works when there is no fetch.
- **C2:** a fetched catalogue that differs from the pin is refused, and not saved.

**Info:** the works themselves rely on the commit pin and TLS, with no per-work hash, and a saved work note stays editable in a shared vault. The index only lists ids from the pinned catalogue.

## 3. Size caps and cancel (#592)

**From reading:**
- `boundedText` refuses a declared `content-length` over the cap.
- It caps the decompressed stream as it reads, then cancels the reader.
- The caps are 16 MB for the catalogue and 8 MB for a work.
- The progress toast's Cancel passes an AbortSignal down to every fetch.

**`t/pin.mjs`:**
- **C3:** a body over the cap with no length header stops after 10 chunks of 1 MB; it is not read whole.
- **C4:** cancel stops every worker. 8 requests of 12 were made, and nothing was written after the abort.
- **C5:** one failing work (a 500) stops the other workers. 4 requests of 12 were made, and nothing was written.

**Info:** when the response has no stream body (only in some engines), the text is read whole before the size check.

## 4. JSON quoting (`t/quote.mjs`)

**Q2, 2/2 pass:** U+2028 and U+2029 in a Ben-Yehuda title and genre. `parseWorkNote` reads the real id, and YAML sees no extra key.

**Q3, 7/7 pass:** dataset values with ```` ```` ````, a newline then ```` ```` ````, `~~~`, U+2028 then ```` ``` ````, U+2029 then ```` ``` ````, a leading ```` ``` ```` and `` a`b`c ``.
- micromark sees exactly one ```dataset block in every case, with nothing of the value outside it.
- Backticks are written as ```. U+2028 is not a CommonMark line ending, so it can't close the fence.
- A value holding U+2028 makes `parseBlock` drop that one field, which fails safe.

### RR25-2 (LOW, confirmed): one Knesset note can break every saved law

**Where:** `store.ts:106` (`parseLawNote`).
- It reads fields with `/^k: (.*)$/m`.
- In JavaScript, `^` and `$` with the `m` flag also match at U+2028 and U+2029, and `JSON.stringify` leaves those characters raw.

**Effect** (**Q1 FAILS**, 2/2):
1. A law name holding U+2028 or U+2029 is cut in the middle of its quoted value.
2. `JSON.parse` throws.
3. `savedLaws()` then throws for **every** saved law: lookups, the dialog's local results and "Ask the law" all fail.

No field was forged: the citation URL is built from the law's id.

**Fix:**
- Parse the note with `parseProperties`, the YAML parser, which read the same note correctly; or escape U+2028/U+2029 in `yaml()`.
- Skip a note that doesn't parse, instead of throwing.

### RR25-3 (LOW, confirmed): the attribution line under a dataset block is not quoted

**Where:** `attribution()` (`snapshot.ts:176`, and the CBS line at `:172`). It embeds the remote title and organization raw.

**Effect** (**Q4 FAILS**, 3/3):
- A line break splits the credit line into separate paragraphs.
- `# ` makes a heading.
- A Markdown link inside the title is live.
- From reading: a title holding `<!--` would hide the rest of the note, the credit included, both in the preview and on export.

**Fix:** pass the title and organization through `oneLine()` and escape them inside `attribution()`.
